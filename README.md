# Bonus Plus — бэкенд программы лояльности

Ядро вашей замены БонусПлюс: база данных баллов + реализация **LoyaltyAPI МойСклад**
(https://dev.moysklad.ru/doc/api/loyalty/1.0/), которая позволяет кассе МойСклад
(«Касса МойСклад» на Windows/Linux/macOS/Android) обращаться в вашу систему за балансом,
расчётом скидки и проведением операций напрямую при сканировании карты клиента.

## Что уже реализовано

- `POST /api/loyalty/counterparty` — МойСклад создаёт нового покупателя → мы заводим
  счёт лояльности и **автоматически генерируем ему номер карты** (штрихкод).
- `GET /api/loyalty/counterparty?search=...` — поиск покупателя (по номеру карты,
  телефону, email) — то, что происходит при сканировании штрихкода на кассе.
- `POST /api/loyalty/counterparty/detail` — баланс баллов покупателя.
- `POST /api/loyalty/retaildemand/recalc` — расчёт скидки/баллов «вживую», пока
  кассир пробивает товары (ничего не меняет в базе, только считает превью).
- `POST /api/loyalty/retaildemand` — закрытие чека: здесь баллы реально
  списываются/начисляются, с защитой от повторной обработки одного и того же чека.
- `POST /api/loyalty/retailsalesreturn` — возврат товара: находит операции по
  исходной продаже и разворачивает их.

## Что ещё предстоит (следующие шаги)

  правил начисления вместо ручного редактирования таблицы `Settings`).
- Виджет/эндпоинт для личного кабинета InSales (отдельная задача — обсудим отдельно).
- Скрипт разовой миграции текущих клиентов (сгенерировать штрихкоды всем существующим
  контрагентам МойСклад и залить туда номер карты).
- Подтверждение операций кодом (SMS) — эндпоинты `/counterparty/verify` и
  `/retaildemand/verify` в спецификации — пока не реализованы, при необходимости
  добавляются по той же схеме, что и остальные.
- Подарочные сертификаты (`GET /giftcard`) — пока не реализовано.

## Облегчённая версия без LoyaltyAPI (пока ждёте доступ разработчика)

Пока личный кабинет разработчика МойСклад не выдан, можно уже сейчас запустить
упрощённую версию на обычном JSON API — она не требует никакой регистрации,
только токен из настроек вашего аккаунта.

**Как это работает:** при закрытии розничной продажи в кассе МойСклад отправляет
вебхук на ваш URL → бэкенд забирает полную продажу по обычному JSON API → находит
или создаёт клиента (с автогенерацией штрихкода) → начисляет баллы по вашим
правилам → пишет актуальный баланс обратно в доп. поле контрагента "Баланс баллов",
чтобы он был виден прямо в карточке клиента в МойСклад.

**Главное отличие от полной версии (LoyaltyAPI):** начисление происходит
*постфактум*, через секунды-минуты после закрытия чека, а не в моменте на кассе.
Живого расчёта скидки и автоматического "оплата баллами" в чеке эта версия не даёт —
списание баллов кассиру придётся оформлять вручную обычной скидкой на нужную сумму.

### Настройка

1. Получите токен доступа: в веб-версии МойСклад → Настройки → Параметры пользователя
   / API (точный путь может отличаться в зависимости от версии интерфейса) →
   создайте токен доступа.
2. Добавьте в `.env`: `MS_API_TOKEN` и придуманный `MS_WEBHOOK_SECRET` (любая
   длинная случайная строка, например `openssl rand -hex 32`).
3. Примените новую миграцию (добавилось поле `pointsAttributeId` в таблицу `Settings`):
   ```bash
   npx prisma migrate dev --name add_points_attribute
   ```
4. Задеплойте проект (см. раздел «Деплой на Vercel» выше), чтобы получить публичный URL.
5. Зарегистрируйте вебхуки в МойСклад — по одному запросу на каждое событие:
   ```bash
   curl -X POST "https://api.moysklad.ru/api/remap/1.2/entity/webhook" \
     -H "Authorization: Bearer ВАШ_MS_API_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{
       "url": "https://ваш-домен.vercel.app/api/webhook/moysklad?secret=ВАШ_MS_WEBHOOK_SECRET",
       "action": "CREATE",
       "entityType": "retaildemand"
     }'
   ```
   И то же самое ещё раз с `"entityType": "retailsalesreturn"` — для возвратов.
6. Сделайте тестовую розничную продажу на кассе МойСклад и проверьте логи Vercel —
   там будет виден сырой payload вебхука. Это важно: я не смог на 100% свериться с
   точным форматом тела вебхука по открытой документации (она рендерится через JS
   и недоступна для автоматической проверки) — код разбирает наиболее
   распространённый для МойСклад формат `{"events": [...]}`, но если в логах
   окажется другая структура — код в `src/app/api/webhook/moysklad/route.ts`
   нужно будет подправить под неё. Это одна правка в одном месте.
7. Аналогично стоит на практике перепроверить, что запись в поле "номер дисконтной
   карты" (`discountCardNumber`) через обычный JSON API действительно ложится в то
   же поле, что использует касса при сканировании — это предположение по аналогии
   с LoyaltyAPI, а не подтверждённый факт. Если после теста поле не заполняется —
   гляньте точное имя через `GET /entity/counterparty/metadata`.

### Когда придёт доступ к LoyaltyAPI

Обе версии используют общую бизнес-логику (`src/lib/loyalty.ts`, таблицы `LoyaltyAccount`
и `PointsTransaction`) — переход на живую версию не потребует переписывать данные,
просто добавится путь с расчётом скидки в реальном времени поверх уже накопленной базы.


## Важная особенность идентификации клиента

В LoyaltyAPI МойСклад есть два режима поиска покупателя: **внутренний** (когда
клиентская база живёт в МойСклад) и **внешний** (когда за поиск отвечает подключённая
система лояльности). Для вашего сценария — свои штрихкоды, которые МойСклад
изначально может не знать — нужен **внешний** режим поиска. Это настраивается на
странице настроек скидок в МойСклад при активации решения.

## Запуск локально

1. Установите зависимости:
   ```bash
   npm install
   ```
2. Поднимите Postgres — проще всего через [Neon](https://neon.tech) или
   [Vercel Postgres](https://vercel.com/storage/postgres) (у обоих есть бесплатный тариф).
3. Скопируйте `.env.example` в `.env` и заполните `DATABASE_URL` и `MS_LOYALTY_AUTH_TOKEN`
   (токен — любая длинная случайная строка, например `openssl rand -hex 32`).
4. Примените схему БД:
   ```bash
   npx prisma migrate dev --name init
   ```
5. Запустите:
   ```bash
   npm run dev
   ```

## Деплой на Vercel

1. Залейте проект в репозиторий на GitHub.
2. Импортируйте репозиторий в Vercel.
3. Подключите Postgres (Vercel Storage → Postgres, или впишите внешний `DATABASE_URL`
   от Neon/Supabase) и добавьте `MS_LOYALTY_AUTH_TOKEN` в Environment Variables.
4. После первого деплоя примените миграции на продовую базу (можно локально,
   указав в `.env` продовый `DATABASE_URL`, и выполнить `npx prisma migrate deploy`).
5. Ваш базовый адрес для МойСклад — `https://<ваш-домен>.vercel.app/api/loyalty`.

## Регистрация решения в МойСклад

Это отдельный шаг, не покрытый кодом в этом репозитории — нужно:

1. Получить доступ к личному кабинету разработчика МойСклад
   (https://dev.moysklad.ru/doc/api/vendor/1.0/#lichnyj-kabinet-razrabotchika).
2. Создать черновик **серверного решения** с блоком `<loyaltyApi/>` в дескрипторе
   (решение можно сделать приватным — только для вашего аккаунта, без публикации
   в общем каталоге).
3. В настройках решения указать базовый адрес (`.../api/loyalty`) и токен —
   тот же, что в `MS_LOYALTY_AUTH_TOKEN`.
4. На странице настроек скидок в МойСклад активировать бонусную программу,
   привязанную к вашему решению, и выбрать внешний режим поиска покупателей.

Логика активации/настроек (обработка `SettingsRequired`, iframe настроек) описана
в отдельной спецификации: https://dev.moysklad.ru/doc/api/vendor/1.0/ — её ещё
предстоит реализовать отдельным небольшим модулем, когда дойдём до этого шага.

```bash
# Посмотреть баланс

```

## Настройка правил начисления/списания

Пока — напрямую через `npx prisma studio`, таблица `Settings` (единственная строка):

- `earnRatePercent` — сколько % от суммы покупки начисляется баллами (по умолчанию 5%).
- `redeemRateRub` — курс списания, 1 балл = сколько рублей (по умолчанию 1).
- `maxPaymentPercent` — максимальный % чека, который можно оплатить баллами (по умолчанию 50%).
- `welcomeBonus` — баллы за регистрацию нового клиента (по умолчанию 0).
